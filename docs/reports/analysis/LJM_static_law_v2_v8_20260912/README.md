# LJM v2~v8 실험 결과 — 동료 검토용

**LJM 추출 힌트 추가로 평균 F1은 0.3031→0.3416으로 올랐지만, v3·v6는 악화됐습니다. v4가 가장 유망하며, 현재 방식을 전 항목에 일괄 적용하기는 어렵습니다.**

## 무엇을 비교했나

- 데이터: 제공 dev 200건. 조건별 v2~v8 1,400판정, 총 2,800판정.
- 기준 조건: 전체 공고 원문·메타데이터 + 해당 항목의 배포 법령 요약·발췌.
- 가설 조건: 기준 조건과 동일한 입력 + LJM 원본 코드의 후보 플래그·추출 문맥.
- Gemma: 로컬 Gemma 4 26B A4B NVFP4, thinking OFF, 출력 한도 512. RAG 검색 없음.
- 그룹: 21그룹 설정의 항목별 독립 대화 방식을 따르되, 이번에는 v2~v8만 실행했습니다. 평소 규칙으로 처리하는 v2·v3도 이번 실험에서는 Gemma가 판정했습니다.
- 후보가 아닌 공고도 전부 Gemma에 입력했습니다. 원본 LJM 탐지 규칙은 수정하지 않았습니다.

## 주요 수치

F1은 0~1이며 높을수록 좋습니다. FP는 오탐, FN은 미탐입니다.

| v3 실적금액 초과 | 0.889 | 0.762 | 2/0 | 5/0 |

| **7항목 평균 F1 / 오류 합계** | **0.3031** | **0.3416** | **378/2** | **267/6** |

바뀐 판정 229개 중 기존 오탐 168개를 고쳤지만, 새로운 오탐 57개와 미탐 4개가 생겼습니다. 실제 양성은 47개이며, 탐지 수는 45→41개입니다.

추론 시간은 507.5→532.0초(+4.8%)입니다. 양쪽 모두 실패·재시도·출력 길이 초과·검색 0건입니다. 다만 힌트 조건의 양성 308개 중 145개에는 유효한 원문 인용 근거가 남지 않았습니다.

## 어떻게 해석하면 되나

- **v4:** 실제 양성 6건을 모두 유지하면서 오탐을 크게 줄였습니다. 민간 실적도 허용하는 조건과 평가 배점을 필수 참가자격에서 구별한 개선 사례가 있습니다.
- **v3:** 힌트 추가 후 오탐만 3건 늘었습니다. 실적 하한 1억원이 추정가격 약 3.27억원보다 작은데도 위반으로 바뀐 사례가 있어 수치 검증이 필요합니다.
- **v6:** 양성 6건 중 3건을 놓쳤습니다. 후보와 제한 문구를 제대로 제공해도 Gemma가 놓친 사례가 있습니다.
- **v7:** F1은 올랐지만 미탐도 늘었습니다. 원본 추출기에서는 같은 지역 토큰의 반복으로 후보가 켜지는 문제를 재현했습니다. 실제 지역명을 나열한 조건의 누락도 확인했습니다.
- **v2·v8:** 개선 폭이 작고 오탐이 여전히 많습니다.

원본 스캐너의 후보 플래그를 최종 판정처럼 간주한 참고 평가에서는 v2 F1=0.933, v3=1.000이었습니다. 그러나 스캐너 전체는 양성 47개 중 24개를 놓쳤습니다. 후보 추출 성능과 최종 법령 판정 성능을 구별해야 합니다.

## 꼭 알아야 할 실험 한계

1. 단일 dev 200건 결과입니다. 평균 F1 차이의 공고 단위 bootstrap 95% 구간은 -0.0138~+0.0795로, 일반화된 개선을 확정하지 못합니다. 대회 전체 24항목 점수도 아닙니다.
2. 두 조건 모두 법령을 직접 넣었습니다. **법령 직접 주입과 RAG의 우열을 비교한 실험은 아닙니다.**
3. v3는 이번 Gemma 실험에서 법령 초안의 ‘추정가격 1배 초과’를 사용했습니다. 원본 스캐너는 ‘배정예산 초과’, 항목표는 ‘1배수 이상 / 사업예산 기준’이므로 해석 차이가 있습니다.
4. v4의 물품·용역 실적 기준은 2.3억원을 사용했습니다. 원본 스캐너가 지방계약에 쓰는 5억원과 다릅니다. 지방 지역제한용 행안부 고시액의 미확인 분기는 임의 수치로 보충하지 않았습니다.
5. 힌트 문맥은 중복 제거 후 최대 1,600자, 문맥당 최대 500자로 표시했습니다. 원문은 자르지 않았습니다. 파싱된 금액 배열을 직접 주입한 실험은 아닙니다.
6. 정답 라벨은 추론 이후 채점에만 사용했고 결과를 본 뒤 프롬프트를 조정하지 않았습니다. 기존 LJM 코드의 과거 dev 활용 여부는 통제하지 못했습니다.

## 채점 재현

표와 CSV는 GitHub에서 바로 확인할 수 있습니다. 채점을 재실행하려면 프로젝트의 고정 의존성을 준비하고, 별도 제공된 원본 `dev.jsonl`과 `dev_labels.csv`를 저장소의 `data/`에 배치하세요. 공고 원본 데이터와 모델 가중치는 이번 게시물에 포함하지 않았습니다.

저장소 루트에서 다음을 실행합니다. 모델 추론을 다시 하지 않고 저장된 응답을 검증·채점합니다.

```bash
uv sync --locked
uv run --locked python analysis/LJM_static_law_v2_v8_20260912/reproduce.py score
```

Gemma 추론까지 재실행하는 절차와 출력 경로 설정은 [상세 보고서의 재현 항목](report.md#재현-및-산출물)을 참고하세요. 현재 게시물은 실험 결과와 재현 자료이며, 운영 중인 추론 코드에 적용한 변경은 없습니다.

실험 폴더는 동료 이니셜 규칙에 따라 `LJM_`으로 변경했습니다. 실행 당시 `source/`와 로그 안의 소문자 경로는 이력 보존을 위해 그대로 두었습니다. `reproduce.py`가 경로만 메모리에서 바꾸어 채점·추출 점검을 실행합니다. 변경 이력과 원본 해시는 `relocation.json`을 참고하세요.
