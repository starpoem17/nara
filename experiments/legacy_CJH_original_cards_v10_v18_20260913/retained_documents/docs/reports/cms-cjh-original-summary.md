# [폐기됨 — 가설 검증 결과로 사용 금지] CMS·CJH 원문 판정카드 dev200 실험 결과

CMS 폐기 실험의 로컬 입력·원응답·평가·로그와 전용 상세 보고서는 사용자 지시로 완전히 삭제했다. 아래 과거 요약은 유효한 실험 결과나 복구 대상으로 사용하지 않는다. 현재 CMS 결과는 [수정 카드 실험 보고서](analysis/CMS_updated_cards_v19_v24_dev200_20260913/report.md)를 참조한다.

승인한 입력으로 CMS 1,200회, CJH 1,800회 생성을 모두 완료했다. 가장 두드러진 현상은 **원문 카드와 최소 JSON 지시문을 함께 준 조건에서, 모델이 요청과 다른 출력 구조를 자주 사용한 것**이다. 중첩 객체나 다른 키의 답을 임의로 변환하지 않았으므로, 아래 유효 응답 수는 사전에 확정한 파서 기준이다. 이 실험의 F1만으로 두 동료의 판단 가설이 맞거나 틀렸다고 단정할 수 없다.

| 실험 | 독립 항목 | 전체 응답 | 판독 유효 | 무효 | 512토큰 종료 | 순수 추론 | 입력 캐시 재사용 | 실제 최대 동시 요청 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| CMS | v19–v24, 6개 | 1,200 | 410 (34.17%) | 790 | 10 | 622.689초 | 63.47% | 15 |
| CJH | v10–v18, 9개 | 1,800 | 29 (1.61%) | 1,771 | 10 | 837.169초 | 70.72% | 16 |

전체 추론은 약 **24분 20초**였다. 설정 상한은 16개이며, CMS에서 관측된 최대는 15개다. 생성 재시도·응답 수정·무효의 정상값 대체는 모두 0회다. 각 항목은 dev 200건 전부를 한 번씩 받았으며, 다른 항목의 답을 전달받지 않았다.

**410개와 29개도 모두 완결 코드펜스 안의 JSON이었다. 요청한 bare JSON 형식을 그대로 충족한 응답은 두 실험 모두 0개다.** 완결 코드펜스는 미리 정한 규약에 따라 내용만 판독하되 형식 위반을 별도로 기록했다. 이 규약은 추론 전에 고정했다.

## 어떤 형식으로 응답했는가

다음은 원응답의 구조만 집계한 관찰이다. 다른 구조에서 판정값을 복원해 재채점하지 않았다.

| 원응답 구조 | CMS | CJH |
|---|---:|---:|
| 요청한 최상위 `위반여부`, `근거문구` 키 | 410 | 29 |
| 현재 항목 안에 두 키를 넣은 중첩 객체 | 580 | 608 |
| 현재 항목의 `v번호`, `e번호` 키 | 0 | 837 |
| 그 밖의 키·객체 구조 | 115 | 181 |
| 하나의 완결 JSON으로 판독되지 않는 출력 | 95 | 145 |

예를 들어 CMS `PPS-DEV-01/v19`는 `{"v19":{"위반여부":0,"근거문구":null}}`, CJH `PPS-DEV-02/v10`은 `{"v10":0,"e10":null}` 형태를 코드펜스 안에 반환했다. 숫자가 보이더라도 사전 파서에서는 `wrong_keys`로 남긴다. 키 이름 변경이나 중첩 해제도 수행하지 않았다.

무효 사유는 CMS에서 키 불일치 695개·완결 JSON 판독 실패 85개·길이 종료 10개, CJH에서 각각 1,626개·135개·10개였다. JSON 뒤에 설명을 덧붙인 경우도 임의로 JSON 부분만 잘라 읽지 않았다. 구체적인 형식별 예시 ID와 항목별 분포는 CMS 형식 관찰 기록(사용자 지시로 삭제됨), [CJH 형식 관찰](../../analysis/CJH_original_cards_v10_v18_20260913/output_observations.json)에 있다.

사전 규약대로 기록된 유효 응답 Macro F1은 CMS 0.533333, CJH 0이다. 무효 응답을 모두 포함할 경우 가능한 Macro F1 하한–상한은 CMS 0.031519–0.854293, CJH 0–0.967320이다. 이 범위는 누락된 판정값의 가능한 배치를 계산한 값이며, 신뢰구간이나 별도 복원 점수가 아니다.

### CMS 원응답 사례

- v22는 유효 51개에서 TP 2·FP 0·FN 0이지만, 나머지 149개는 무효였다.
- v23은 `PPS-DEV-03`에서 정답 0에 대해 1, `PPS-DEV-140`에서 정답 1에 대해 0을 냈다. `PPS-DEV-054/v23`처럼 JSON 뒤에 상세 설명을 이어가다가 512토큰에서 끝난 출력도 보존했다.
- v24의 유효 양성 10개는 모두 근거 문자열이 어느 한 공고 문서의 연속된 원문 인용과 일치하지 않았다. 공고와 meta를 비교하는 설명을 근거 필드에 쓰는 사례가 있었다. 이 진단 때문에 판정값을 바꾸지는 않았다.
- **승인된 v24 원문 자체에 dev 정답 정보가 있다.** 해당 원문을 그대로 유지했다. `PPS-DEV-049`·`062` 원응답은 중첩 객체 안에 `위반여부: 0`을 썼지만 키 불일치로 무효였고, `071`은 유효 판독된 1이었다. 앞의 두 숫자는 원응답 내용에 대한 기술이며 추가 채점에 넣지 않았다. 원문에 정답 메모가 포함된 v24 결과는 독립 검증이 아니다.

### CJH 원응답 사례

- 유효 양성은 v12의 5개뿐이었고 모두 dev 라벨 기준 FP였다: `PPS-DEV-076`, `103`, `138`, `155`, `169`. 각 근거는 직접생산확인증명서를 요구하는 문구를 인용했다. 이 관찰만으로 제품 분류 단계의 오류 원인을 확정하지 않는다.
- `PPS-DEV-178/v10`은 앞의 JSON에 `v10: 1`을 쓰고, 뒤 설명에는 제공 목록에 없으므로 0이라는 내용을 쓰다가 512토큰에서 끝났다. 후보 목록을 언급하는 응답 내부의 불일치가 그대로 남아 있다. 뒤의 설명으로 앞의 값을 교정하지 않았다.
- v15·v16 및 v17·v18은 **각 쌍의 두 응답이 모두 유효한 공고가 각각 0/200건**이다. 상세 평가에 기록된 동시 양성 0건은 배타성 준수의 증거가 아니다. 독립 응답을 합쳐 상호 보정하지 않았다.

전체 오류·양성·무효 사례와 가공하지 않은 응답은 상세 보고서 및 각 실험의 `errors.csv`, `cases.csv`, `per_feature/`, `responses/`에 있다. 근거가 공고 원문에 연속된 문자열로 존재하는지, 부재탐지 근거가 비어 있는지 등의 진단도 유효 판독된 응답만 대상으로 했다.

## 경쟁제품 목록 제공에서 실험자가 정한 부분

**후보 선정 방식은 CMS·CJH가 제안한 판단 규칙이 아니라 이번 실험자가 정한 자료 제공 조건이다.** 실시간 모델 RAG 대신 주최 측 패키지의 원문을 미리 첨부하는 방식으로 승인받았다. 다음 선정은 정답·기존 예측을 보기 전에 고정했다.

1. 원문 문서 또는 `meta.세부품명번호목록`에서 경쟁제품 CSV의 10자리 번호가 정확히 일치하는 행.
2. 문서에 2자 이상 세부품명이 문자 그대로 나타나는 행. 1자 명칭은 이 문자 일치 경로에서만 제외하며 다른 경로로는 선택될 수 있다.
3. 전체 문서를 BGE 기준 2,048토큰·128토큰 중첩으로 나누고 전체 meta를 별도 질의로 삼아, 각 CSV 행의 최대 코사인 유사도 상위 5개. 동점은 원본 행 순서로 처리한다.

세 집합의 합집합을 원본 CSV 순서로 붙였다. 원본 616행 가운데 공고별 5–13행, 평균 6.07행이 선택됐다. 모든 열과 특이사항을 그대로 첨부했고, 점수·선정 이유·경쟁제품 해당 여부를 모델에 새 판단으로 전달하지 않았다. 동일 공고의 CJH 9개 요청이 같은 후보 행을 받았다. 실제 행·질의·일치 위치·점수와 출처 해시는 [후보 원문 기록](../../analysis/CJH_original_cards_v10_v18_20260913/product_candidates.jsonl.gz), [선정 규약](../../analysis/CJH_original_cards_v10_v18_20260913/selection_protocol.json)에 있다.

이 방식은 관련 행을 빠뜨리거나 무관한 행을 포함할 수 있다. 이번 결과에는 그 영향과 모델의 카드 해석이 함께 포함되며, 저자 고유의 검색 구현이나 후보 선정의 완전성을 검증한 결과가 아니다.

법령·고시도 항목별 원문 구간으로 고정했다. 주최 측 패키지는 과거 경쟁제품 지정·고시금액의 모든 버전을 담고 있지 않고, CMS v22 관련 삭제 조항의 과거 문구도 제공하지 않는다. 없는 원문을 외부에서 보충하거나 새 규칙으로 요약하지 않았다. 항목별 출처·원문 구간·범위 메모는 각 실험의 `law_specs/`, `law_provenance.json`, `laws.json`에 남겼다.

## 실행 조건과 충실성 검증

- 모델: 로컬 Gemma 4 26B A4B NVFP4, RTX 5090, thinking OFF, temperature 0, seed 0, 출력 상한 512. 강제 JSON 문법을 사용하지 않았다.
- 문맥: **이번 실험에만 36,864토큰**. 기존 32,768에서는 3,000개 중 107개가 초과했고, 최대 입력+출력은 35,897토큰이었다. 원문을 줄이지 않고 사용자가 승인한 한도만 적용했다. 기본 파이프라인의 한도는 32,768이다. 제출 서버 호환 실험으로 해석하지 않는다.
- 처리: 최대 16개 요청, 완료 시 빈자리 보충, 공고 원문을 먼저 두고 prefill 캐시 공유. 첫 항목 완료 후 다른 항목을 투입했지만 답을 전달하지는 않았다. 공고 최대 3개·공통 입력 48,000토큰의 입장 제한도 유지했다.
- 실제 캐시 입력: CMS 10,916,768/17,201,082토큰, CJH 21,264,032/30,068,003토큰. 이는 재사용 관측값이며, 캐시를 끈 비교 실험에 대한 속도 향상 배수는 측정하지 않았다.
- 자동 후보 선정 29.224초, 최종 입력 준비는 두 실험 합계 누적 59.287초로 별도 기록했다. 원문 전수 검증 시간·설계 시간은 추론 시간에 포함하지 않았다. 모델 로드 32.930초·예열 0.058초는 두 실험이 공유한 1회 비용이다.
- 최초 모델 초기화는 실행 도구 경로 문제로 실패했고 dev 생성은 0개였다. 기존 가상환경 실행기로 경로를 바로잡았다. 실패 로그도 남겼으며, 이후 생성 3,000개에는 재시도가 없다.
- Astra medium은 원문과 계획, 구체적 선정 규약, 초기 구현을 검토했다. 최종 3,000개 입력의 원문·실제 토큰 일치 및 실행 기록 검증은 루트 에이전트가 수행했으며, 이를 Astra의 독립 실행 검증으로 표현하지 않는다.
- 실제 입력 토큰, 원문 카드·공고·첨부 구간, 파일 해시, 3,000개 고유 요청, 512 출력 상한, 독립 실행·캐시·동시 처리 기록을 검증했다. 두 실험의 원응답 해시를 **2026-09-13 02:35:33 KST**에 고정한 뒤 정답을 읽었다. 관련 합성 테스트 22개도 통과했다.
