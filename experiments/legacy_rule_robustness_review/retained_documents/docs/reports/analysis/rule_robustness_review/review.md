# 동료 설명과 우리 규칙의 비교 및 표현 변화 점검

운영 코드는 수정하지 않았다. `scan_candidates.py` 원본이 없어 동료의 실제 파서와 직접 비교한 결과는 아니다. 동료의 자연어 설명과 현재 구현을 대조했다.

## 확인된 차이

- 참가자격 영역: 동료는 의미 수준으로 명시했다. 우리는 제목 90자 한도, 제목 뒤 허용 문구, 번호 형태, 종료 키워드를 추가했다. 이러한 세부 조건은 원본 코드에서 확인된 것이 아니다.
- 서식·평가 제외: 동료의 의도와 같지만 우리 구현은 일부 제목 패턴으로 구간을 닫는 방식이다. 서식이라는 문맥을 지속적으로 기억하지 않으며, 뒤에 참가자격 제목이 나오면 다시 후보 구간을 열 수 있다.
- v2: 물품·제조·용역 필터와 지방 수의계약+특수기술/공법 예외가 우리 코드에 있다. 제공된 동료 설명에는 이 구체 조건이 없다. 이번에 제안했던 C와는 별개로 초기 구현에 이미 있던 조건이다.
- v3: 동료 설명은 요구 실적금액 > 배정예산금액이다. 우리 코드는 v2와 후보 추출을 공유하므로 이상/초과 필요, 같은 조건 내 미만/이하 금지까지 v3에 적용한다. 이는 제공된 설명보다 좁다.
- 미인식 문구/누락 메타데이터: 우리 코드는 0으로 처리한다. 동료 구현의 처리 방식은 미확인이다.

## 표현 변화 점검

같은 의미의 간단한 합성 문장을 고정 규칙과 현재 규칙에 입력했다. 사례와 실행 결과는 `probes.json`에 보존했다. 이 점검은 실패 사례를 찾기 위한 것으로 독립 검증 성능을 추정하지 않는다.

- 제목에 `및 실적요건`만 추가하면 기존 (1,1)에서 현재 (0,0)으로 바뀐다. 신규 회귀다.
- 제목 뒤 괄호를 전각 괄호로 바꾸면 기존 (1,1)에서 현재 (0,0)으로 바뀐다. 신규 회귀다.
- 실적과 금액 사이에 빈 줄을 추가하면 기존/현재 모두 놓친다.
- `입찰서 제출일까지 다음 자격을 갖춘 업체`는 현재도 구간을 닫는다. 제출마감일을 포함한 일부 표현만 보완했다.
- 서식 제목의 괄호를 `【】`에서 `〈〉`로 바꾸면 현재도 서식의 금액을 참가자격으로 오인한다.
- 서식 제목 다음에 `입찰참가자격`이 나오면 현재도 해당 서식 내용을 후보로 잡는다.
- 요구 실적금액 2억원과 배정예산 1억원을 제공해도 `이상/초과`가 없으면 v3=0이다. 동료 설명과의 차이를 보여주는 의미 수준 점검이다.

## 판단

dev의 점수 개선이 일반화를 입증하지 않는다. 공고 ID나 정답을 실행 코드에 넣지는 않았지만, dev 오류를 보고 추가한 제목 허용 패턴은 확인되지 않은 표현에 더 취약해졌다. 문서 구조 개선 방향은 타당하나 현재 일부 구현은 과도하게 제한적이다.

동료 규칙을 그대로 사용하면 안 된다고 볼 근거는 없다. 원본 코드와 실행 설정을 확보해 수정 없이 같은 입력으로 재현하는 것이 먼저다. 현 구현은 동료 원본의 복제가 아니라 설명을 바탕으로 독립 구현한 것이다. 동료가 우리보다 일반화가 좋다는 근거도 현재 없다.

동료와 현재 규칙은 v2 F1 93.3%, v3 F1 100%로 총점이 같지만 v2 오탐은 동료 보고서 DEV-138, 우리는 PPS-DEV-059이다. 이 차이의 원인은 원본 코드 없이는 확정할 수 없다. 원본의 내용 기반 오탐 제거보다 059 하나를 맞추기 위한 C 추가를 우선할 이유는 없다.

다음 검증은 동료 원본과 우리 버전을 모두 동결한 뒤, 공고 정답을 바꾸지 않는 제목/기호/줄바꿈 변형과 별도 미사용 라벨 데이터로 비교해야 한다. 현재 dev를 다시 나누어도 이미 전체 정답을 확인했으므로 새로운 독립 검증셋이 되지 않는다.
